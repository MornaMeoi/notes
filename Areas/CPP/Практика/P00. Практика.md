# Ступени к Змейке

Основная линия. Каждая задача — деталь будущего проекта, а не упражнение в стол.

## Ступень 1. Один класс, один инвариант
Опора: [[Инварианты]], [[Время жизни]], [[Rule of Five]], [[RAII]]

**E1. `Grid<T>` — игровое поле** `[Классы]`
Непрерывное хранение, `operator[](i, j)` в стиле C++23, инвариант размеров, rule of zero.
*Подвох:* соблазн сделать `T** data` и `operator[]`, возвращающий строку.
*Приёмка:* ни один из пяти методов не написан руками, `m[i, j]` работает, выход за границы диагностируется.

**E2. `FileHandle` — RAII над `FILE*`** `[Классы]`
Единственная задача класса — владеть сырым ресурсом. Пятёрка пишется руками.
*Подвох:* копирование. Решить осознанно — глубокое, запрещённое или move-only.
*Приёмка:* двойного закрытия нет, можно вернуть из функции, нельзя случайно скопировать.

**E3. `SnakeBody` — тело змейки** `[Классы]`
Выбор контейнера под «добавить голову / убрать хвост». Инвариант: связная цепочка соседних клеток без самопересечений.
*Подвох:* проверять инвариант в каждом методе вместо того, чтобы его держать.
*Приёмка:* рост и движение за `O(1)`, самопересечение — не линейным поиском.

## Ступень 2. Иерархия
Опора: L06 — LSP, виртуальный деструктор, `final`, срезка

**E4. `IRenderer` — абстракция вывода** `[Иерархии]`

*Приёмка:* второй рендерер не трогает ни строчки модели.

**E5. Диагностика сломанной иерархии** `[Иерархии] [Диагностика]`
Даю код, нарушающий подстановку Лисков. Найти, назвать ломающийся предикат, починить.

**E6. Наследование → композиция** `[Иерархии]`
Рефакторинг иерархии, где наследование использовано вместо композиции.

# Копилка по лекциям

Мелкие прицельные задачи, выпавшие из разбора. Помечено, куда именно целится.

## L01
**T1. LRU-кэш** `[Классы]` — канон курса. `std::list` + `unordered_map<K, list::iterator>`, `splice` для перемещения. Сравнить с идеальным кэшированием по Беладѝ на записанной трассе.

## L02
**T2. Список, который нельзя сломать снаружи** `[Классы]` — инкапсуляция так, чтобы инвариант «нет петель» держался конструктором, а методы его не проверяли.
**T3. Найти протечку состояния** `[Диагностика]` — дам класс, где `private` на месте, кастов нет, а инвариант всё равно рушится снаружи. → *твой промах по инвариантам, вопрос 4*

## L03
**T4. Баг в списке инициализации** `[Диагностика]` — найти без запуска, объяснить, показать флаг компилятора, который ловит. → *твой промах, вопрос 4*
**T5. Copy-and-swap** `[Классы]` — присваивание со строгой гарантией, самоприсваивание бесплатно.

## L04
**T6. Поймать тихую деградацию move** `[Диагностика]` — дам класс, где одна безобидная строчка превратила все перемещения в копирования. Найти по счётчикам, починить. → *твой промах, вопрос 6*

## L05
**T7. PImpl с `unique_ptr`** `[Классы]` — собрать целиком, включая move-операции в `.cpp`. → *твой промах, вопрос 7*
**T8. Строгий алиасинг** `[Диагностика]` — воспроизвести расхождение на `-O2`, починить через `std::bit_cast`. → *твой промах, вопрос 3*
**T9. Функтор против указателя на функцию** `[SOLID]` — замерить `std::sort` на обоих, объяснить разницу цифрами.

## L06
**T10. Виртуальный вызов из конструктора** `[Иерархии] [Диагностика]` — воспроизвести, объяснить через порядок установки `vptr`. → *твой промах, вопрос 3*
**T11. Иерархия с `clone`** `[Иерархии]` — абстрактная база, виртуальный деструктор, виртуальное копирование, проверка на срезку.
