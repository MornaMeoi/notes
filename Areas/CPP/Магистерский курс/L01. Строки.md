## Строки в стиле C
#### Hello, world!
• Самый простой код, какой только возможен.
```cpp
std::cout << "Hello, world!" << std::endl;
```
#### Строковые литералы
• `"Hello, world!"` - это строковый <span style="color: purple;">литерал</span>, т.е. константа времени компиляции.
• Ещё пример литералов: `0x1000`, `1.6e-2`, `'c'`, `true`, `nullptr`.
• Примеры строковых литералов: `u8"Hello"`, `u"Hello`, `U"Hello"`, `L"Hello"`.
```cpp
std::cout << R"(h
e
l
l
o)" << std::endl;
```
#### Типы и преобразования
• Его тип - это <span style="color: purple;">const char[14]</span>, так как `sizeof("Hello, world!") == 14`.
• Это, например, означает, что `"Hello, world!"[0]` - это не ошибка.
```cpp
const char* decayed = "Hello, world!"; // array-to-pointer
```
• Какие ещё преобразования мы знаем?
#### Интермедия: преобразования
• Последовательность стандартных преобразований всегда начинается с не более чем одного из трёх преобразований.
```cpp
int a = 5, b;
b = a + 2; // lvalue to rvalue

int a[10], int* b;
b = a; // array to pointer

int foo(int);
int (*b)(int);
b = foo; // function to function pointer
```
• Как вы думаете, будет ли тут side effect?
```cpp
volatile std::nullptr_t a = nullptr; int* b; b = a;
```

#### Обсуждение
• Проблемы безопасности при работе с C-строками.
• Главна проблема: при передаче в функцию вроде `strcpy` указателя на неправильные данные, мы получим в ответ **ВСЕ** данные до ближайшего нулевого символа.
#### Вариант решения в стиле C
• Функции с ограничением количества символов:
```cpp
char* strncpy(char* dst, const char* src, size_t n);
char* strncat(char* dst, const char* src, size_t n);
int strncmp(const char* s1, const char* s2, size_t n);
```
• Работает ли этот вариант?
• Это лучше, чем ничего, но есть очевидные проблемы:
	• функции, для которых так не сделать (напр. `strlen`)
	• off-by-one проблемы с завершающим нулём и его переносом
	• переполнения буфера из-за рассогласования переданного и реального размера

#### Обсуждение
• Настоящая причина проблем в том, что для C-строки длина не является инвариантом.
• Чтобы сохранять инварианты таких объектов как строки, необходимо закрытое состояние, недоступное к модификации, т.е. необходима <span style="color: blue;">инкапсуляция</span>.
• Что естественным образом приводит к идее: написать класс строки.

#### Обсуждение: формируем строки
• Прямое сложение.
```cpp
std::string a = ssl ? "https" : "http";
a = a + "://" + path + "/" + query;
```
• Потоки ввода-вывода.
```cpp
std::stringstream ss;
ss << (ssl ? "https" : "http") << "://" << path << "/" << query;
```
• Форматирование.
```cpp
auto fmt = std::format("{}://{}/{}", (ssl ? "https" : "http"), path, query);
```
Лектор отмечает, что  `std::format`, всё же, не работает. И приводит пример:
```cpp
#include <iostream>
#include <format>
#include <sstream>
#include <string>

void foo(bool ssl, const char* path, const char* query) {
	std::stringstream ss;
	ss << (ssl ? "https" : "http") << "://" << path << "/" << query;
	std::cout << ss.str() << std::endl;
}

void bar(bool ssl, const char* path, const char* query) {
	auto fmt = std::format("{}://{}/{}", (ssl ? "https" : "http"), path, query);
	std::cout << fmt << std::endl;
}

int main() {
	foo(true, "mysite", "?q=1");
	bar(false, "othersite", "?q=2");
}
```
Вывод в gcc и clang:
```
fatal error: format: No such file or directory
```
Вывод в Visual Studio (msvc?):
```
https://mysite/?q=1
http://othersite/?q=2
```
#### Проблема #2: статические строки
• Что вы думаете об использовании константных статических строк?
```cpp
static const std::string kName = "FOO";
// .....
int foo(const std::string& arg);
// .....
foo(kName);
```
• Идея выглядит плохой: мы добавляем heap indirection. "FOO" - это литерал. При загрузке программы он будет скопирован в кучу.
• Что вы думаете о замене статической строки указателе?
```cpp
static const char* kName = "FOO";
// .....
int foo(const std::string& arg);
// .....
foo(kName);
```
• Стало ещё хуже: теперь мы попадаем на создание временного объекта при каждом вызове функции foo.
#### Решение: string_view (C++17)
• `std::string_view` - это невладеющий указатель на строку.
```cpp
static const std::string_view kName = "FOO";
// .....
int foo(const std::string_view& arg);
// .....
foo(kName);
```
• Здесь нет ни heap indirection, ни создания временного объекта.

```cpp
std::string str = "   trim me  ";

vtrim.remove_prefix(std::min(trimfst, vtrim.size()));
auto trimlst = vtrim.find_last_not_of(" ");
vtrim.remove_suffix(vtrim.size() - std::min(trimlst, vtrim.size()));
```
