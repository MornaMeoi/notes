# Время жизни

## Суть
Обращение к объекту вне его времени жизни — **неопределённое поведение**.
Всё остальное в этой теме — следствия из этого одного факта.
## Почему так
Время жизни легко спутать с областью видимости, но это **разные оси**:

| | Свойство чего | Про что | Когда определяется |
|---|---|---|---|
| **Область видимости** (scope) | имени | *места* в тексте программы, откуда можно обратиться | компиляция |
| **Время жизни** (lifetime) | объекта | *моменты* исполнения, когда состояние валидно | выполнение |

Совпадают они только в частном случае автоматической переменной. Два контрпримера ломают склейку:

```cpp
void f() {
    static int x = 0;   // область видимости: блок f
}                       // время жизни: до конца программы

int* p = new int(5);    // имени нет вовсе, значит нет и области видимости
                        // время жизни есть: до delete
```

Время жизни начинается, когда **завершилась инициализация**, а не когда выделена память.
Отсюда следует, что через `malloc` объект с конструктором создать нельзя: память будет, времени жизни — нет, объект окажется в невалидном состоянии.
**Висячим** (dangling) называется указатель или ссылка на объект, чьё время жизни истекло.
Важно: сама по себе висячая ссылка безвредна. Неопределённое поведение наступает
только в момент **обращения** по ней.
## Примеры

| Категория объекта | Время жизни |
|---|---|
| Автоматический (на стеке) | от инициализации до выхода из блока |
| Временный | до конца **полного выражения** |
| Статический, глобальный | от инициализации до конца программы |
| Динамический | от `new` до `delete`, области видимости нет вовсе |

Полное выражение не всегда совпадает с инструкцией: временные внутри условия `if`,
в аргументах вложенных вызовов и в частях `for` умирают в конце своего полного выражения.
## Продление жизни
Время жизни временного объекта можно продлить **константной lvalue-ссылкой** — тогда оно становится равно времени жизни ссылки. Но продление **локально и однократно**: оно не передаётся через границу функции, поэтому возврат константной ссылки из функции всё равно даёт висячую ссылку.
## Подводные камни

```cpp
const std::string& f() { return std::string("x"); }   // висячая: продление не переживает return

const int& a = 5;                 // ок: связывание напрямую с временным
const int& b = std::max(5, 6);    // висячая!
```

Вторая строка — классика собеседований. `std::max` возвращает `const int&`, то есть
ссылка связывается **не с временным объектом, а с другой ссылкой**. Прямого связывания нет, продление не срабатывает, временный умирает в конце выражения.
Ещё две ловушки:
- Продление **не работает для полей класса**. Ссылка-член, связанная с временным в списке инициализации, провисает сразу после конструктора.
- Неконстантная lvalue-ссылка вообще отказывается связываться с временным — и это защита: запись через неё ушла бы в объект, который никто больше не увидит, и потерялась бы молча.
Компиляторы диагностируют висячие указатели и ссылки **плохо**. Рассчитывать на предупреждение нельзя, помогают только ASan и внимательность.

- [[RAII]] — держится целиком на этом понятии: деструктор вызывается в конце времени жизни, и потому освобождение ресурса гарантировано

- [[Exception safety]] — при раскрутке стека время жизни автоматических объектов заканчивается принудительно
