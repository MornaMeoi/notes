# RAII

## Суть
Деструктор — единственное место, где освобождение ресурса **гарантировано**.
Всё остальное это надежда на то, что управление дойдёт до нужной строки.

## Почему так
При исключении стек разматывается, и на этом пути вызываются **только деструкторы**
автоматических объектов. Ни одна твоя строка между точкой броска и `catch` не выполнится.

Отсюда и ответ на вопрос, почему в C++ нет `finally`: деструктор **и есть** `finally`.
Только он привязан не к блоку, а ко времени жизни объекта — и потому срабатывает
одинаково при `return`, при `break` и при исключении.

Это же объясняет, почему схема с `goto cleanup` из [[L04. RAII и перемещение]]
выглядит рабочей, но ею не является. Она чинит ранние `return` — то есть те выходы,
которые ты **написал сам**. Исключение создаёт выход, которого нет в твоём коде,
и метка `cleanup` до него не достаёт. Одна точка освобождения, до которой надо
*дойти*, гарантией не является. Гарантия — деструктор.

## Что из этого следует
Гарантии безопасности из [[L08. Исключения]] — не отдельная тема, а прямое продолжение:

| Гарантия | Что обещает | Чем достигается |
|---|---|---|
| Базовая | нет утечек, объекты согласованы | почти бесплатно, если ресурсы в RAII-обёртках |
| Строгая | commit/rollback, состояние не изменилось | copy-and-swap |
| Бессбойность | `noexcept` | фундамент для строгой: swap и деструктор не бросают |

**Линия Калба** — граница, которую полезно провести в уме при проектировании операции:
выше неё всё может бросать, но ничего не изменено; ниже — всё изменяется, но ничто не бросает.

## Пример
Копирующее присваивание со строгой гарантией. Вся суть — в расположении линии Калба:

```cpp
class Buffer {
    std::size_t size_ = 0;
    int*        data_ = nullptr;

public:
    explicit Buffer(std::size_t n) : size_{n}, data_{new int[n]{}} {}

    Buffer(const Buffer& rhs) : size_{rhs.size_}, data_{new int[rhs.size_]} {
        std::copy_n(rhs.data_, rhs.size_, data_);
    }

    void swap(Buffer& rhs) noexcept {   // noexcept обязателен, иначе строгой гарантии нет
        std::swap(size_, rhs.size_);
        std::swap(data_, rhs.data_);
    }

    Buffer& operator=(const Buffer& rhs) {
        Buffer tmp{rhs};   // ← выше линии Калба: может бросить, но *this ещё не тронут
        swap(tmp);         // ← ниже линии: noexcept, изменяет, но не бросает
        return *this;
    }                      // ~tmp освобождает старый буфер

    ~Buffer() { delete[] data_; }
};
```

Самоприсваивание тут корректно само собой — проверка `if (this != &rhs)` не нужна.

> [!note] Как это выглядит сегодня
> Заменяешь `int* data_` на `std::vector<int> data_` — и весь класс исчезает:
> ни деструктора, ни копирования, ни swap, компилятор сгенерирует всё корректно.
> Это **rule of zero**, и это правильный ответ в рабочем коде.
> Пример выше нужен, чтобы понимать, что `vector` делает у тебя за спиной.

## Подводные камни
- Деструктор по умолчанию `noexcept`. Исключение из деструктора во время размотки → `std::terminate`.
- Написал один из специальных методов — должен написать остальные (rule of three/five), иначе двойное освобождение.
- `std::swap` в C++98 делал копию через временный объект, то есть **мог бросить**. Поэтому для строгой гарантии свой `swap`, а не библиотечный.
- `noexcept` — это обещание, а не пожелание. Соврал → `std::terminate` без раскрутки.
