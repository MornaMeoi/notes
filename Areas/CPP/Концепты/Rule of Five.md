# Rule of Five

## Суть
Если классу понадобился хотя бы один из пяти специальных методов — значит он **владеет
ресурсом вручную**. А значит сгенерированные компилятором версии остальных четырёх
заведомо неверны, и писать их придётся все.

Пятёрка: копирующий конструктор, копирующее присваивание, перемещающий конструктор,
перемещающее присваивание, деструктор. **Конструктор по умолчанию в неё не входит.**

Ресурс — не только память: файловый дескриптор, мьютекс, сокет, соединение с БД,
хендл ОС. Память просто самый частый случай.

## Почему так
Компилятор генерирует копирование почленно. Для `struct A { int x; double y; };` это
заведомо правильно, для `struct B { int* p; };` — заведомо неправильно. Причина не в
сложности типа, а в том, чего система типов **не выражает**:

> Компилятор не знает, **владеет** ли класс тем, на что указывает.
> Тип `int*` означает «адрес int» и ничего больше.

Класс с владеющим `int* p = new int[n]` и класс с наблюдающим `int* p = &чужой[i]`
для системы типов **неотличимы**. Компилятор обязан выбрать умолчание и выбирает
единственное универсально безопасное — скопировать значение указателя. Для наблюдателя
это ровно верно. Для владельца — двойное освобождение.

По той же причине `~Buffer() = default` для владеющего сырого указателя это утечка:
дефолтный деструктор разрушает поля, а разрушение `int*` — пустая операция.

## Тихая деградация move → copy
Самая опасная часть правила. Перемещение может незаметно превратиться в копирование
двумя разными путями:

```cpp
struct B { Probe p; ~B() {} };     // объявлен деструктор -> move-операции не генерируются
B b2 = std::move(b1);              // -> копирование

const Buffer c1(10);               // источник константный
Buffer c2 = std::move(c1);         // const Buffer&& не связывается с Buffer&&
                                   // -> копирование
```

Ни ошибки, ни предупреждения. Причина одна:

> Перемещение — это **оптимизация**, а не отдельная операция.
> Копирование всегда остаётся семантически корректной заменой.

Компилятор честно провёл разрешение перегрузки и нашёл подходящий вариант.
Программа корректна — она просто медленнее, а за скорость компилятор не отвечает.

**Асимметрия правил.** Объявишь копирование или деструктор — *тихо* потеряешь перемещение.
Объявишь перемещение — *громко* потеряешь копирование: оно будет **явно удалено**,
и класс станет move-only, как `std::unique_ptr`.

```
error: use of deleted function 'M::M(const M&)'
note: implicitly declared as deleted because 'M' declares a move constructor
```

Асимметрия неслучайна: копирование — безопасная замена перемещению, а наоборот нет.

## Как объявлять пятёрку
Объявить не значит написать тело:

- **`= delete`** — копирование этому типу не нужно. Так устроены `unique_ptr`, `lock_guard`, `ofstream`: они move-only.
- **`= default`** — нужно штатное поведение, но объявить обязан, потому что объявил что-то другое.

Нюанс, который любят на собеседованиях, — **место** `= default` решает тривиальность типа:

```cpp
struct A { A(const A&) = default; int x; };   // trivially copyable
struct B { B(const B&); int x; };
B::B(const B&) = default;                      // НЕ trivially copyable: user-provided
```

Потеря тривиальности лишает тип права на `memcpy`-оптимизации внутри STL.

## Правило нуля
Правило нуля — не отрицание правила пяти, а его **следствие**: пятёрку кто-то всё равно
пишет, но не ты. Её пишут авторы `std::vector`, `std::string`, `std::unique_ptr`.

```cpp
class Buffer { std::vector<int> data; };   // ни одного из пяти методов не нужно
```

Работает это потому, что владение закодировано **в типе** поля. `unique_ptr<int[]>` сам
сообщает компилятору: я владею, я удаляю, меня нельзя копировать, меня можно перемещать.
Сгенерированные методы становятся правильными автоматически.

Практический вывод: сырое владение должно жить в одном крошечном классе, а все остальные
классы держат его полем и не пишут ничего.

## Подводные камни

**Деструктор ради постороннего дела.** Класс не владеет ничем вручную, но кто-то дописал
`~Widget() { log("destroyed"); }`. Все перемещения в классе молча стали копированиями.
Код компилируется, тесты проходят, поведение побайтово то же — меняется только скорость.
Находится профилировщиком через полгода, а не компилятором за секунду.

**Написать копирующий конструктор и забыть присваивание.** Тогда `a = b` всё ещё
поверхностное: утечка старого буфера плюс двойное освобождение. Втроём или никак.

**Самоприсваивание.** `a = a` в наивной реализации сначала освобождает своё, потом
копирует из уже освобождённого. Лечится проверкой `this != &rhs` или copy-and-swap
(см. [[RAII]]).

**Перемещение из `const`.** `const` на локальной переменной, которую потом возвращают
или передают дальше, тихо убивает перемещение.
